# อัปเดตโปรเจกต์: Dobot MG400 Lab TA Chatbot

**วันที่:** 14 กรกฎาคม 2026  
**สถานะ:** ใช้เป็นต้นแบบในห้องแล็บได้แล้ว  
**โฟกัสถัดไป:** ลองใช้จริง แล้วค่อยปรับ UI / เติมความรู้ตามที่เจอ

---

## โปรเจกต์นี้คืออะไร

เราทำ **แชทบอทช่วยเรียน/ช่วยสอน** สำหรับหุ่นยนต์ **Dobot MG400**

นักศึกษาหรืออาจารย์ถามเรื่องหุ่นได้ เช่น

- สเปกเครื่อง (น้ำหนักยก, ระยะเอื้อม)
- ความปลอดภัยก่อนสั่งเคลื่อนที่
- ต่อเน็ต / ต่อ TCP ยังไง
- ใช้ DobotStudio
- เขียน Python เชื่อมหุ่น
- โครงงาน demo ต่าง ๆ

บอทจะ **ค้นจากเอกสารจริง** แล้วตอบ ไม่ใช่เดาสุ่มจากอินเทอร์เน็ต

ทุกอย่างรันบนเครื่องเราเอง (local) ไม่ต้องพึ่ง cloud

---

## ตอนนี้ทำถึงไหนแล้ว

สรุปสั้น ๆ: **ระบบครบแล้ว ใช้ได้แล้ว**

| เรื่อง | สถานะ |
|--------|--------|
| ดึงเอกสาร + ตัดเป็นชิ้นความรู้ | เสร็จ |
| เก็บลงฐานข้อมูลค้นหา (Chroma) | เสร็จ |
| ตอบคำถามด้วย LLM (Ollama) | เสร็จ |
| หน้าแชท (Streamlit) | เสร็จ ใช้ได้ |
| ทดสอบ 50 คำถามจริง | เสร็จ คะแนนดี |
| ปรับ prompt ให้ไม่ปฏิเสธเกินจำเป็น | เสร็จ |
| แก้บั๊ก index หายหลังอัปเดตข้อมูล | เสร็จ |

## ทำงานยังไง (ภาพง่าย ๆ)

```text
เอกสาร MG400
    ↓
ตัดเป็นชิ้นความรู้ (preprocess)
    ↓
เก็บลงฐานค้นหา (ingest)
    ↓
มีคนถาม → หาชิ้นที่เกี่ยวข้อง
    ↓
LLM สรุปคำตอบ + อ้างอิงเอกสาร
    ↓
โชว์ในหน้าแชท
```

**เปิดใช้:** รัน Streamlit แล้วเปิดเบราว์เซอร์ที่  
`http://localhost:8501`

## เอกสารที่ใส่ในระบบ

เราเลือกแบบ **แน่นและสะอาด (tight)**  
ไม่เอาทุกไฟล์ในโฟลเดอร์ เพราะของเยอะเกินจะทำให้ตอบหลุดหัวข้อ

### เก็บไว้
- คู่มือ MG400
- คู่มือ DobotStudio / CRStudio
- คู่มือ TCP/IP + ตัวอย่าง Python
- คู่มือ demo / โครงงาน
- FAQ ที่ทำความสะอาดแล้ว
- ชีทสรุปที่เราเขียนเอง (สเปก, พอร์ต, safety, โครง Python)

### ตัดออก (เพราะเสียงดัง / ใช้ยาก)
- หน้าเว็บขายของ / case ตลาด
- ไฟล์ alarm ยาว ๆ
- SDK ภาษาอื่นที่ยังไม่จำเป็น (C++, C#, ROS)
- PDF เสีย / สแกนแล้วอ่านไม่ออก
- ไฟล์ซ้ำ ๆ

**ขนาดตอนนี้**
- ประมาณ **46 แหล่งเอกสาร**
- ประมาณ **1,079 ชิ้นความรู้**

---

## ผลทดสอบ

เราลองถามประมาณ **50 ข้อ** แบบที่น่าจะเจอในห้องแล็บ

| รอบ | ผล |
|-----|-----|
| ก่อนปรับ system prompt | ดี 46 ข้อ / อ่อน 4 ข้อ · คะแนนเฉลี่ย 4.70/5 |
| หลังปรับ system prompt | **ดีครบ 50 ข้อ** · คะแนนเฉลี่ย **4.94/5** |

### ปัญหาที่เคยเจอ แล้วดีขึ้น
- บอทปฏิเสธตอบทั้งที่มีข้อมูล (over-refusal) → แก้ด้วย prompt
- เอกสารรบกวนการค้นหา → ตัด noise + จัดอันดับผลค้นหาใหม่
- บาง PDF ใช้ไม่ได้ → ทำชีทสรุปทดแทน
- หลังอัปเดต index แล้ว UI พัง → แก้ให้โหลด collection ใหม่ได้

### ข้อควรรู้
- คะแนน 50 ข้อเป็น **ตรวจอัตโนมัติ** ไม่ใช่คนอ่านทีละข้อแบบละเอียด
- โมเดลที่ใช้ยังเล็ก บางทีสรุปตัวเลข/รายการอาจเพี้ยนได้เล็กน้อย
- เรื่อง **safety และการสั่งหุ่นเคลื่อนที่** ยังต้องมีคนดูแลอยู่เสมอ

ไม่จำเป็นต้องไปขุดเอกสารเพิ่มทั้งก้อน

**สรุป UI:** ใช้เช็คและ demo ได้แล้ว  
ถ้าจะสวยขึ้น ค่อยทำทีหลังตาม feedback จริง

## งานถัดไปที่แนะนำ

### ทำก่อน (คุ้มสุด)
1. ลองใช้จริงกับนักศึกษา / ตัวเอง 1 รอบ
2. จดคำถามที่ตอบพลาดหรือตอบไม่ชัด
3. เติมเฉพาะจุดที่เจอจริง

### ทำเมื่อจำเป็น
- ตรวจด้วยคนอีก 10–15 ข้อ (เน้น safety, พอร์ต, เน็ต)
- ทำคำตอบตายตัวสำหรับเรื่องที่ห้ามเพี้ยน (เช่น เลขพอร์ต)
- ปรับ UI ให้อ่านง่ายขึ้น (ปุ่มคำถามด่วน, เตือน safety, โชว์แหล่งอ้างอิงชัด ๆ)

### ยังไม่ต้องรีบ
- ใส่เอกสารกลับทั้งก้อน
- เปลี่ยนระบบใหญ่ / ย้ายขึ้น cloud
- อัปโมเดล (ค่อยคิดถ้าเจอว่าตอบเพี้ยนบ่อย)
